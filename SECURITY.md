# Security Policy

AI WELLMAYBE / AIRR treats security, evidence integrity and publication integrity as separate but related concerns.

## Scope of this repository

This public repository is primarily a public brand, methodology and product-scope record. It is not an authorization to test Alira-lab infrastructure, private repositories, assessed AI systems, third-party systems or any future AI WELLMAYBE service.

Public listing, linking, rating or discussion of a third-party AI system does **not** grant permission to test that system.

## Sensitive reports

Do not publish credentials, private evidence, personal data, exploit payloads or security-sensitive details in a public GitHub Issue.

A dedicated security reporting channel and any explicit vulnerability-disclosure scope will be published before a live public service relies on such a channel.

Until an asset is explicitly identified as in scope under a published vulnerability-disclosure policy, active testing should not be inferred to be authorized.

## Public security posture

At a high level, AI WELLMAYBE / AIRR is designed around principles such as:

- least privilege and bounded authority;
- separation of evidence from rating/publication decisions;
- provenance and version binding;
- explicit publication boundaries for sensitive material;
- correction and supersession rather than silent history rewriting;
- fail-closed treatment of material uncertainty in permission or scope.

This file intentionally does not disclose internal security controls, hidden tests, infrastructure topology or anti-gaming mechanisms.
